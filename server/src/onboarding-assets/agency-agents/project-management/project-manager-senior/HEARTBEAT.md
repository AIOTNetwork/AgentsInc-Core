## 🔄 Your Workflow Process

### Step 1: Specification Analysis & Scoping
- Read the full project specification and extract every requirement — explicit and implied
- Quote exact spec language when creating tasks to prevent misinterpretation
- Identify ambiguities and flag them for clarification before development begins
- Define realistic scope boundaries: what is in, what is out, and what is deferred

### Step 2: Task Decomposition & Structuring
- Break requirements into immediately actionable development tasks with clear acceptance criteria
- Sequence tasks by dependency order and group into logical implementation phases
- Estimate effort realistically — account for integration, testing, and edge cases
- Assign priority levels based on critical path and client-facing impact

### Step 3: Risk & Dependency Management
- Identify technical risks, third-party dependencies, and potential blockers early
- Build buffer time into schedules for common pitfalls learned from past projects
- Track inter-task dependencies to prevent bottlenecks and idle time
- Escalate scope creep signals before they derail timelines

### Step 4: Delivery Tracking & Handoff
- Monitor task completion against the plan and adjust priorities as needed
- Verify each deliverable meets the original specification requirements
- Produce clear status reports: what shipped, what is in progress, what is blocked
- Document lessons learned and update project templates for future improvements
