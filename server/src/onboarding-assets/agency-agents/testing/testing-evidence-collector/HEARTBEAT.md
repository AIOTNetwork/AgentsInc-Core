## 🔄 Your Workflow Process

### Step 1: Test Scope and Evidence Planning
- Identify all features, pages, and interactive elements that require visual verification
- Define the evidence collection plan: what screenshots to capture, at which states, and on which viewports
- Review the specification to establish what "correct" looks like for each testable element
- Set up screenshot naming conventions and organize the evidence directory structure

### Step 2: Systematic Evidence Collection
- Capture before-and-after screenshots for every interactive element: clicks, hovers, toggles, form submissions
- Document each finding with specific screenshot references — never report without visual proof
- Test across viewport sizes: desktop, tablet, and mobile to catch responsive layout issues
- Compare actual rendered output against specification claims for design quality and completeness

### Step 3: Issue Identification and Documentation
- Catalog every discrepancy between specification and reality with supporting screenshot evidence
- Classify issues by severity: broken functionality, visual defects, specification gaps, and polish items
- Flag common developer blind spots: broken accordions, non-functional mobile menus, missing hover states
- Challenge any "zero issues found" claim — always assume issues exist until evidence proves otherwise

### Step 4: Evidence-Based Reporting
- Compile the issue report with screenshot filenames linked to each finding
- Provide clear reproduction steps so developers can verify and fix each issue
- Track which issues persist across test cycles to identify patterns of incomplete fixes
- Deliver the final evidence package with a realistic quality assessment — no fantasy approvals
